# Инструкция по использованию `run_comparison.py`

Скрипт `run_comparison.py` предназначен для автоматизированного сравнения различных конфигураций SpQR, с особым фокусом на настройку **адаптивного порога (adaptive threshold)** за счет **послойной (depth-wise)** и **модульной (module-wise)** чувствительности.

## Концепция адаптивного порога

Вместо использования строго фиксированного порога квантования (по умолчанию `--outlier_threshold 0.2`) для всей сети, скрипт позволяет динамически масштабировать этот порог для конкретных типов модулей или слоев на определенной глубине. Итоговый (эффективный) порог для каждого слоя рассчитывается так:

```text
effective_threshold = outlier_threshold / (module_sensitivity * layer_sensitivity)
```

*   **Множитель > 1**: *Снижает* порог, что позволяет сохранить больше outlier-весов (используйте для высокочувствительных модулей, таких как `down_proj`, `o_proj`).
*   **Множитель < 1**: *Повышает* порог, отсекая больше outlier-весов в пользу сжатия (хорошо подходит для менее чувствительных `up_proj`, `gate_proj`).
*   **Множитель = 1**: Эквивалентен базовому порогу для этого модуля/слоя.

### Глобальный адаптивный порог по статистике весов (`adaptive_outlier_threshold`)
Помимо статического перераспределения квоты (presets/sensitivities), вы можете включить полностью динамический расчет базового порога для каждого слоя на основе статистики распределения его весов (например, дисперсии). 

Для этого используются два специальных параметра:
*   `--adaptive_outlier_threshold` — включает автоматический расчет базового порога.
*   `--outlier_adaptation_factor` — множитель, регулирующий агрессивность этого расчета (по умолчанию 1.0). 

*Важно: модульная и послойная чувствительность (module/layer sensitivities) накладывается поверх этого расчетного базового порога, что дает максимальную гибкость!*

Суть механизма — перераспределить квоту outlier-весов ("outlier capacity") в те слои и модули, где они больше всего нужны для минимизации потерь качества (без использования дорогих grid search-методов).

## Основные примеры использования

### 1. Настройка модульной чувствительности (Module-wise)
Позволяет переопределять множители для специфичных слоев (например, для MLP или Attention-блоков). Через `--module_sensitivities` можно передать сразу несколько конфигураций для параллельного тестирования:

```bash
python run_comparison.py \
    --model_path /path/to/model \
    --dataset c4 \
    --module_sensitivities "down_proj=1.4,o_proj=1.2,up_proj=0.9,gate_proj=0.9" \
    --skip_preset
```

### 2. Настройка послойной чувствительности (Depth-wise)
Позволяет задавать множители для разных участков сети. Можно использовать индексы слоёв, диапазоны или алиасы (`early`, `mid`, `late`):

```bash
python run_comparison.py \
    --model_path /path/to/model \
    --dataset c4 \
    --layer_sensitivities "0-7=0.95,8-23=1.0,24-31=1.15" "early=0.90,mid=1.0,late=1.10"
```

### 3. Комбинирование (Module + Depth)
Используйте флаг `--combine_module_depth` для перебора декартова произведения всех переданных модульных и послойных множителей:

```bash
python run_comparison.py \
    --model_path /path/to/model \
    --dataset c4 \
    --module_sensitivities "down_proj=1.4,up_proj=0.9" \
    --layer_sensitivities "0-7=0.95,8-31=1.05" \
    --combine_module_depth
```

### 4. Использование глобального адаптивного порога
Вы можете запускать `run_comparison.py`, применяя динамический адаптивный порог (вместо жесткого `0.2`) в качестве базы для всех тестов:

```bash
python run_comparison.py \
    --model_path /path/to/model \
    --dataset c4 \
    --quick \
    --adaptive_outlier_threshold \
    --outlier_adaptation_factor 1.5
```

## Анализ результатов

После завершения расчетов скрипт выведет сравнительную таблицу и сохранит её в JSON-файл в директории `comparison_results/`. В результатах следует обращать внимание на две ключевые метрики:

1. **PPL (Perplexity)** — (Wikitext2, C4, PTB). Чем ниже, тем лучше. Будет показан процент относительного изменения к квантованному baseline.
2. **OL share (global_ol_share)** — глобальная доля outlier-весов в %.
